# 디지몬 토큰 테이머 설계 문서

> AI 코딩 도구의 토큰 사용량으로 디지몬 어드벤처 파트너를 키우는 macOS 메뉴바 앱.
> 레퍼런스: [PokeTokenBar](https://github.com/chattymin/PokeTokenBar) (구조), DigiMonTokenBar (Choisiz, MIT; 디지몬 데이터 참고)
> 비공식 팬 프로젝트이며 Bandai/Toei와 관련이 없습니다.

---

## 1. 컨셉과 범위

- 포켓몬처럼 "많이 잡는" 게임이 아니라, 디지몬 세계관답게 **파트너(친구)를 키우는** 앱.
- 대상은 **디지몬 어드벤처 1기 주인공 파트너 8계열**뿐이다.
- 계열당 6단계: 유년기 I, 유년기 II, 성장기, 성숙기, 완전체, 궁극체.
- 분기 진화는 없다. 원작의 정식 진화 루트 한 줄만 쓴다.
- 총 48종이다.
- **제외 또는 보류:** 오메가몬, 암흑진화(스컬그레이몬 등), 아머체(페가수스몬, 네페르티몬).

## 2. 육성 시스템

### 2.1 디지타마 (알)
- **무늬가 계열을 정한다.** 계열마다 원작의 고유 디지타마가 있다. 랜덤 알은 쓰지 않는다.
- **첫 알은 무료다.** 사용자가 8종 중 하나를 고른다.
- **상점에서는 아직 시작하지 않은 계열의 알만 판다.** 이미 키운 계열은 수첩과 파트너 보관함에 남아 있으므로 다시 살 필요가 없다.
- **부화하면 유년기 I이 된다.** 유년기 II는 고르는 단계가 없다. 원작처럼 계열마다 정해져 있다.

### 2.2 진화 조건 (확정: 원작 순서 = B안)

| 진화 | 조건 |
|---|---|
| 유년기 I → 유년기 II → 성장기 | 게이지 100%이면 자동 진화 |
| 성장기 → 성숙기 | 게이지 100% + **디지바이스** |
| 성숙기 → 완전체 | 게이지 100% + **펜던트** + **문장이 빛남** |
| 완전체 → 궁극체 | 게이지 100% + **유대 레벨** (아이템 없음) |
| 궁극체 이후 | 게이지가 유대 레벨로 쌓인다 |

- **원작 근거:** 1기에서는 태그(펜던트)에 문장을 끼우고, 문장이 빛나면 완전체가 된다. 궁극체는 1기에서 워그레이몬과 메탈가루몬만 특별한 사건(빛의 화살과 워프진화)으로 도달했다. 8계열 모두에 통하는 원작 규칙이 없으므로 유대 레벨로 둔다. 빛의 화살 연출이나 워프진화 보상 같은 원작 장치는 넣지 않기로 했다.
- **퇴화는 없다.** 진화는 한 방향이다.
- **표시 형태 선택:** 설정에서 수첩에 등록된 형태 중 아무거나 골라 메뉴바에 띄울 수 있다. 이건 보이는 모습만 바꾸며 육성 상태는 그대로다. 기본값은 지금 키우는 파트너의 현재 형태다.

### 2.3 진화 가능 표시 "!"
- **진화 조건이 모두 충족됐을 때만** 메뉴바 캐릭터의 오른쪽 위 대각선 바깥에 주황색 "!"가 통통 튄다. 평소에는 보이지 않는다.
- 진화는 사용자가 "!"를 눌러 시작한다. 진화 장면이 재생된다.
- 무엇이 부족한지는 "!"가 아니라 **팝오버 카드의 게이지 아래 조건 줄**에서 항상 보여 준다.
  - 예: `완전체까지 ✓ 진화 게이지 100% ✓ 펜던트 · 용기의 문장 (57%)`

### 2.4 문장
- 계열마다 **고정 배정**된다. 부화하는 순간 어떤 문장인지 정해진다.
- **상점에서 팔지 않는다.** 업적을 달성하면 빛난다.
- 업적은 **8계열 모두 같은 난이도**로 둔다. 이름만 계열별로 다르게 붙인다.
  - 예: 용기의 시련 = "성숙기로 7일 함께하기". 수치는 미정이다.
- 진행도는 펜던트가 없어도 쌓인다. 문장은 펜던트를 사야 끼울 수 있다.
- 상태는 세 가지다: 꺼짐(회색 + 진행도), 끼움(펜던트 안의 회색 문장), 빛남(문장 색 + 반짝임).

### 2.5 상점 아이템

| 아이템 | 종류 | 역할 |
|---|---|---|
| 고기 | 소모품, 싸다 | 게이지와 유대를 올린다. 먹기 모션이 나온다. |
| 디지바이스 | 파트너마다 1회 구매 | 성장기 → 성숙기 진화의 열쇠 |
| 펜던트 | 파트너마다 1회 구매, 가장 비싸다 | 문장을 끼우는 장비이자 완전체 진화의 열쇠. 성숙기부터 상점에 나온다. |
| 디지타마 | 계열마다 1회 | 아직 시작하지 않은 계열의 알 |

- 이름은 "태그"가 아니라 **펜던트**로 통일한다. 원작을 모르는 사람도 바로 알아본다.
- **DigiMonTokenBar와의 차이:** 그쪽 펜던트는 경험치 소모품(+100M)이다. 우리 앱에서 그 역할은 고기가 맡는다.
- **가격과 게이지 기준값:** 아래 §2.6의 1차 값으로 구현했다. 확정이 아니며 조정할 수 있다.

### 2.6 1차 밸런스 값 (구현 2026-11-14, `Tamer/TamerBalance.swift`)

DigiMonTokenBar 기준을 근거로 잡았다. 하루 평균 약 253M 토큰, 일반 라인 졸업 750M, 알 5M, 디지바이스 100M이다. 토큰은 상류처럼 **성장 게이지와 상점 지갑에 동시에** 들어간다. 지갑은 사용 누적에서 지출 누적을 뺀 값이다. 그래서 아이템은 주는 성장보다 비싸게 둔다.

| 항목 | 값 | 비고 |
|---|---|---|
| 부화 | 5M | 넘친 토큰은 유년기 I로 이월 |
| 게이지: 유년기 I / II | 15M / 30M | 차면 자동 진화, 넘친 토큰은 이월 |
| 게이지: 성장기 / 성숙기 / 완전체 | 100M / 200M / 300M | 100%에서 멈추고 이월하지 않음. "!" 대기 |
| 게이지: 궁극체 | 300M | 찰 때마다 유대 Lv +1 |
| 문장의 시련 | 성숙기 상태에서 **토큰을 쓴 날 7일** | 8계열 공통. 펜던트가 없어도 진행 |
| 유대 | 100점 = Lv 1, 궁극체 조건 Lv 5 | 고기 1개 = 유대 +50, 게이지 +5M |
| 가격: 고기 / 디지바이스 / 펜던트 / 디지타마 | 10M / 100M / 300M / 200M | 펜던트가 가장 비쌈 |

- 진화 아이템(디지바이스, 펜던트)은 진화할 때 없어지지 않고 파트너의 장비로 남는다.
- 설치 전에 쓴 토큰은 세지 않는다. 첫 갱신이 기준점이다. 장부 규칙은 DigiMonTokenBar의 프로바이더별 장부를 그대로 옮겼다.
- 새 디지타마를 사면 그 알이 지금 파트너가 되고, 기존 파트너는 보관함으로 간다. 보관 중인 파트너는 자라지 않는다.

## 3. UI

### 3.1 메뉴바
- 캐릭터 도트와 토큰 텍스트를 표시한다. 예: `200.7M · 82%`
- 아이콘 폭은 **약 54pt**로 잡는다. 캐릭터 오른쪽에 "!" 배지가 들어갈 자리를 남기기 위해서다.
- 22pt 이하인 형태는 정수 배율과 nearest-neighbor 보간으로 그린다. 큰 형태는 축소해서 그리며, 모션 랩에서 볼 때 뭉개짐은 문제없었다.
- 문장이 빛나는 순간에는 캐릭터 옆에서 문장 아이콘이 1~2초 반짝인다.

### 3.2 팝오버 파트너 카드 (목업: `assets/build/crest-mockup.html`)
위에서 아래 순서로 다음을 둔다.
1. 캐릭터 무대
2. 이름 · 계열 · 단계
3. 진화 게이지
4. 조건 줄
5. 장비/문장 줄
6. 힌트

장비/문장 줄은 단계에 따라 바뀐다.

| 단계 | 장비/문장 줄 |
|---|---|
| 성장기 | 디지바이스 (필요 → 보유) |
| 성숙기 | 펜던트 (필요 → 꺼진 문장을 끼움 + 시련 진행도 → 빛남) |
| 완전체 | 빛나는 펜던트 + 궁극체까지 유대 Lv |

연출은 세 가지다.
- **디지바이스 획득:** 아이콘이 튀어나온다.
- **펜던트 구매:** 꺼진 문장이 유리창으로 날아 들어간다.
- **문장 빛남:** 화면 중앙에 문장이 커지며 "용기의 문장이 빛났다!"가 뜬다.

### 3.2.1 팝오버 구성 (구현)
- 탭은 파트너, 상점, 수첩이다. 아래에 새로고침, 설정, 종료가 있다.
- 파트너 탭은 위에서부터 파트너 카드, **전체 서비스 · 상세 기록**, 사용 한도 순서다.
- DigiMonTokenBar의 DATA TRAFFIC 패널에서는 "전체 서비스 · 상세 기록"만 남겼다. 프로바이더 탭, 입출력 링, 주/월/프로바이더 레지스터, 활동 띠, 캐시 줄은 뺐다.
  - 남긴 것: 오늘 합계, 이번 주, 이번 달, 이번 달 일별 추이, 프로바이더별 오늘 구성(입력, 출력, 캐시)
  - 상세 기록은 접지 않고 항상 펼쳐 둔다. 프로바이더 행은 선택한 하나가 아니라 오늘 쓴 서비스 전부를 보여 준다.
- 사용 한도 패널은 상류 그대로 두었다. 프로바이더 탭이 없어졌으므로 한도가 있는 서비스끼리만 따로 고른다.
- 팝오버는 목업처럼 밝은 테마로 고정했다. 시스템이 다크 모드여도 같다.

### 3.3 수첩 (도감)
- 계열마다 한 줄씩, 맨 앞에 문장 엠블럼이 있다. 문장을 빛내 본 계열은 엠블럼에 색이 들어간다.
- 6단계 칸이 있고, 아직 못 본 형태는 실루엣으로 보인다.
- 수첩에 등록된 형태는 설정의 표시 형태로 고를 수 있다.

## 4. 모션 (목업: `assets/build/motion-lab.html`)
- **방향:** 모든 스프라이트는 **오른쪽을 본다.** 왼쪽으로 걸을 때는 좌우 반전한다.
- **렌더링:** 정수 도트 단위로 움직이고, 프레임은 steps 방식이다. 보간 없는 픽셀 렌더링을 쓴다.
- **모션 목록:** 대기, 걷기, 기쁨, 먹기(고기), 쓰다듬기(하트), 잠(Z), 삐짐, 진화, 진화 가능(!), 부화. 퇴화는 표시 형태를 바꿀 때 쓰는 연출 확인용이다. **공격은 없다.**
- **진화 장면:** 실루엣이 점점 빠르게 깜빡이며 다음 형태와 교차하다가, 흰 섬광 뒤 새 형태가 나타난다.
- **부화:** 알이 흔들리다 금이 가고, 흰 섬광 뒤 유년기 I이 나온다.
- **프레임 포맷:** `{d, dx, dy, flip, mode:'black'|'white'|'dim', who:'cur'|'next'|'egg'…, ov:[아이콘 오버레이], flash}`. 오버레이 아이콘(고기, 하트, Z, 분노, 음표, 반짝임, 금, !)은 오리지널 도트다.

### 5.1 출처와 규격

| 디지타마 8종 | 16×20 | 나무위키 원작 디지타마 무늬를 도트로 옮김 (`tools/digitama_ref.py`) |
| 문장 8종 | 24×24 | Wikimon **공식 디지바이스 V-Pet 문장 도트**를 1:1로 따고, 공식 태그 일러스트의 색을 입힘 (`tools/crests.py`). 성실은 공식 색이 없어서 회색 |
| 펜던트 | 40×68 | 원작 태그 설정화를 보고 그림. 빈 펜던트, 문장 장착(`_{line}`), 꺼진 문장 장착(`_{line}_off`) |
| 디지바이스 | 40×38 | 원작 어드벤처 디지바이스 설정화를 보고 그림 (`tools/digivice.py`) |
| 고기 | 16×16 | 오리지널 초안. 원작 V-Pet 고기에 맞출지는 미정 |

- 형식은 원래 픽셀 크기의 PNG와 SVG다. SVG는 색마다 `<path>` 하나에 가로 연속 픽셀을 합치고 `crispEdges`를 쓴다.
- 앱에서는 **PNG + SwiftUI `.interpolation(.none)`**을 권장한다.
- `manifest.json`의 각 항목 필드: `{line, stage, name, file, source, wikimonFile, url, placeholder, facing:"right", native:[w,h], png, svg}`

### 5.2 저작권과 배포 원칙 (중요)
- **저작권 에셋은 코드 저장소에 커밋하지 않는다.** `/assets/`는 `.gitignore`에 들어 있다.
- 실제 배포는 PokeTokenBar처럼 한다.
  - 스프라이트는 **별도 저장소에 두고 런타임에 내려받는다.**
  - `~/Library/Application Support`에 캐시한다.
  - 비공식, 비상업 고지를 넣는다.
  - THIRD_PARTY_NOTICES를 둔다.
- **앱이 Wikimon이나 나무위키를 직접 링크해 쓰지 않는다.**
  - Wikimon robots.txt의 Crawl-delay는 60이다.
  - 수집 스크립트는 UA `DigiTokenBar-research/0.1`을 쓰고 요청 사이에 3~5초를 쉰다.

### 5.3 폴더와 빌드
```
tools/                 # 커밋 대상 (코드)
  build_assets.sh      # 전체 재생성. 참고 이미지가 없으면 자동으로 받음
  download_all.py      # Wikimon 스프라이트 → assets/sprites-raw
  handdrawn.py         # 포요몬, 냐로몬
  to_svg.py            # 원래 크기 PNG/SVG + 오른쪽 방향 + manifest
  digitama_ref.py      # 디지타마
  items.py             # 고기
  digivice.py          # 디지바이스

  motion_lab.py        # → assets/build/motion-lab.html
  crest_mockup.py      # → assets/build/crest-mockup.html (#state=…&line=… 로 상태를 바로 열 수 있음)
assets/                # git 제외
  sprites-raw/  handdrawn/  refs/{digitama,crest,pendant,digivice,poyomon-nyaromon}/
```

재생성 명령은 `./tools/build_assets.sh`이다. `.venv`가 없으면 스크립트가 만들고 Pillow를 설치한다.

## 7. 결정 기록 (왜 이렇게 했나)
- **8계열만 다루기:** 디지몬은 포켓몬과 달리 "파트너" 개념이다. 사람들이 원하는 건 주인공 파트너다.
- **분기 진화 없음:** 원작에서도 유년기 II를 고르는 단계가 없다.
- **문장은 상점에서 팔지 않음:** 원작에서 문장은 성장으로 빛나는 것이다. 팔면 업적의 의미가 사라지고, 다른 계열 문장 7종은 쓸모없는 진열이 된다.
- **완전체 조건 = 펜던트 + 문장 (B안):** 원작 순서를 따랐다. 처음 안(A안)은 펜던트를 궁극체 조건으로 두었지만, 원작과 맞지 않아 바꿨다.
- **"!"는 진화 가능할 때만:** 평소에는 화면을 깔끔하게 두고, 조건은 카드에서 확인한다.
- **이름은 태그 대신 펜던트:** 원작을 모르는 사람도 바로 알아본다.
- **아이템과 문장 디자인은 원작에 맞춤:** 문장, 펜던트, 디지바이스, 디지타마 모두 공식 디자인을 기준으로 다시 그렸다.
- **DigiMonTokenBar 코드를 베이스로 하고, 디자인은 직접 만든 것으로 (2026-11-14):** 사용량 수집과 한도는 검증된 상류 코드를 쓴다. 게임과 화면은 이 문서와 목업대로 새로 짰다.
- **DATA TRAFFIC은 "전체 서비스 · 상세 기록"만 남김 (2026-11-14):** 파트너 카드가 주인공이고, 사용량은 서비스 전체 기록 하나로 충분하다.
- **GitHub에서 받아 바로 쓰기 (2026-11-14):** DigiTokenBar처럼 Release zip만 받아도 이미지가 나와야 한다. 앱에는 이미지를 넣지 않고, 별도 공개 저장소에서 첫 실행 때 내려받는다 (§5.2 원칙 유지).
